Building Hexagon Fall Guys Solo

Aug 2, 2026 · 6 min read · Dev Log

Design, scripting, and testing — how one person put together a Fall Guys–style obstacle course in Fortnite Creative, and what broke along the way.

Hexagon started as a two-week experiment: could a single obstacle course, built entirely solo, hold a lobby's attention for more than one run? Almost a year later it's the most played map in the catalog, and the Winter Update pushed its all-time peak past 10,000 concurrent players. None of that was the plan going in.

Starting with the fall, not the course

Most obstacle-course tutorials start with the first obstacle. I started with the fall — the few seconds after elimination where a player free-falls back to the spectator platform. If that moment doesn't feel good, nothing before it matters, because it's the last thing a losing player experiences before deciding whether to queue again.

Everything else — checkpoints, hazards, the wedge sequence people screenshot the most — got built backward from that five-second window.

If the elimination doesn't feel fair, the obstacle doesn't matter.

The checkpoint device loop

Creative's checkpoint devices handle the obvious case — respawn a player where they last stood — but Hexagon needed per-player state for streaks and near-misses too. That meant a small Verse module tracking three things per player: last checkpoint, consecutive clears, and a rolling "close call" counter used to trigger the wedge-tilt VFX. 

player_state := class:
    last_checkpoint : int = 0
    clear_streak : int = 0
    close_calls : int = 0

OnPlayerEliminated(Agent : agent) : void =
    if (State := PlayerStates[Agent]):
        State.clear_streak = 0
        RespawnAt(Agent, State.last_checkpoint)

Nothing exotic — the trick was keeping the state small enough that it never desynced under load, even with sixteen players hitting checkpoints within the same tick.

What actually broke

  1. Checkpoint volumes overlapping at obstacle seams, double-firing the streak counter
  2. The ice-block obstacle desyncing its rotation for late joiners mid-round
  3. A memory leak from spawning VFX on every close call instead of pooling them

The VFX leak was the worst of the three — invisible in testing with two players, and a hard crash by round three with a full lobby. Pooling fixed it in an afternoon; finding it took most of a week.

✎

Dev note: if a bug only shows up with a full lobby, test with a full lobby. Bots don't reproduce timing bugs the way real, laggy, impatient players do.

What shipped in the Winter Update

Three changes made it into the seasonal refresh:

  • A new skybox and lighting pass, mostly for screenshots
  • Two reworked obstacles that were getting skipped via a wallrun exploit
  • A visible streak counter, so the near-miss VFX finally has something to point at

Would I do it solo again?

Yes, mostly because there was no one else to blame for the desync bug, which meant I actually had to understand it instead of filing a ticket. That's the trade-off of doing this alone — slower to ship, but nothing goes out that I can't explain line by line.
